## 1. Design Principles

| # | Principle | What it means in the UI |
|---|---|---|
| 1 | **Explain, don't just score** | Every AI number sits next to its reason. A score never appears without a way to see the evidence. |
| 2 | **Human decides, AI advises** | AI output is labelled as AI. Decision buttons (Shortlist / Reject) are always human actions, never auto-triggered. |
| 3 | **Show the cost before the click** | Any action that calls AI shows a cost estimate and needs explicit confirmation (REQ-FR-028). |
| 4 | **Privacy is visible** | Anonymized views are marked as such. Users can see what was removed and why. |
| 5 | **Degrade without drama** | If AI is slow or down, show a calm "AI delayed" badge, never an error page (REQ-NFR-017). |
| 6 | **Accessible by construction** | AA contrast, keyboard-first, text alternative for every chart, tokens enforce this once. |
| 7 | **Calm, trustworthy, not flashy** | Hiring is high-stakes for both sides. Quiet surfaces, one accent colour, generous whitespace. |
| 8 | **Works on a budget phone** | Emerging-market first: light pages, no heavy JS, readable on 360px wide screens and slow networks. |

## 2. Brand and Voice

### 2.1 Personality
Fair, clear, supportive, precise. Not "disruptive" or hype-driven.

### 2.2 Voice Rules

| Do | Don't |
|---|---|
| "Your match score is 78. Here is why." | "Our AI found you're an amazing fit!" |
| "AI analysis delayed. Showing similarity ranking instead." | "Oops! Something went wrong." |
| "No evidence found in the resume for this skill." | Leave the claim blank or invent support |
| "This estimate is $0.00 on the free plan." | "Free AI magic!" |
| "You decide. The AI only suggests." | "Let AI pick your next hire." |

### 2.3 Microcopy Library (use verbatim)

| Context | Copy |
|---|---|
| AI label | "Generated by AI" |
| Anonymized label | "Personal details removed" |
| Cost modal title | "Confirm AI screening" |
| Cost modal body | "This will screen {n} applications. Estimated cost: {cost}. Nothing is processed until you confirm." |
| Degraded badge | "AI analysis delayed. Using semantic similarity only." |
| Bias pass | "Bias check passed" |
| Bias flag | "Needs human review: language flagged" |
| Empty applications | "No applications yet. Share your job link to get started." |
| Lockout | "Too many attempts. Try again in {mm:ss}." |
| Delete account confirm | "This permanently deletes your data. This cannot be undone." |

### 2.4 Logo and Naming
Wordmark "Match Minds". Icon: two overlapping circles (a match) with a small checkmark. Provide SVG in light, dark and single-colour versions. Minimum size 24px height.

## 4. Typography

### 4.1 Font Stack

| Role | Font | Fallback |
|---|---|---|
| Latin UI + body | **Inter** | `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` |
| Bengali (Phase 5 i18n) | **Noto Sans Bengali** (or Hind Siliguri) | `"Noto Sans Bengali", "Kalpurush", sans-serif` |
| Code / IDs | `ui-monospace, "SF Mono", Menlo, monospace` | — |

> **CSP note:** the PRD's Content-Security-Policy is `default-src 'self'`, with no Google Fonts allowed. **Self-host the fonts** (WOFF2, subset to Latin now and Bengali later) from `/static/fonts/`. Use `font-display: swap`. Budget: Inter 400/500/600/700 only.

### 4.2 Type Scale

Base 16px. Ratio about 1.25. Body line height 1.5.

| Token | Size / Line | Weight | Use |
|---|---|---|---|
| `display` | 36 / 44 | 700 | Landing hero only |
| `h1` | 30 / 38 | 700 | Page title |
| `h2` | 24 / 32 | 600 | Section heading |
| `h3` | 20 / 28 | 600 | Card title |
| `h4` | 16 / 24 | 600 | Sub-heading, table header |
| `body` | 16 / 24 | 400 | Default |
| `body-sm` | 14 / 20 | 400 | Dense tables, help text |
| `caption` | 12 / 16 | 500 | Badges, timestamps (never for essential info) |
| `score` | 48 / 52 | 700 | Match score number |

Rules: minimum 16px for any input text (prevents iOS zoom); line length 60–75 characters for prose; sentence case everywhere; Bengali text gets +0.1 line height.

### 5.3 Breakpoints (mobile first)

| Name | Min width | Layout |
|---|---|---|
| base | 0 | Single column, bottom or drawer nav, 16px side padding |
| `sm` | 640 | Two-column forms |
| `md` | 768 | Sidebar becomes a collapsible rail |
| `lg` | 1024 | Fixed sidebar (240px), content max 1152px |
| `xl` | 1280 | Wide tables, split views (list + detail) |

│ Header: logo · global search · 🔔 notifications · account ▾   │ 56px, sticky
├───────────┬──────────────────────────────────────────────────┤

- Skip link "Skip to main content" is the first focusable element.

## 6. Core Components

Each component lists states and the key accessibility requirement.

### 6.1 Buttons

| Variant | Style | Use |
|---|---|---|
| Primary | `--primary` fill, white text | One per view |
| Secondary | White fill, `--border-input` outline, `--ink` text | Common actions |
| Tertiary | Text only, `--primary-strong` | Low-emphasis |
| Destructive | `--danger` fill, white text | Reject, delete |
| AI action | `--ai-soft` fill, `--ai-ink` text, ✦ icon | "Generate with AI" (always paired with cost note) |

Sizes: `sm` 32px · `md` 40px · `lg` 48px height (mobile primary actions use `lg`).
States: default · hover · focus-visible · active · disabled (`aria-disabled`, 3:1 outline retained) · loading (spinner + "Working…" label, button stays in place and is not removed).

### 6.2 Form Controls

- Label above the field, always visible (no placeholder-only labels). Required fields marked "(required)" in text, not only an asterisk.
- Help text below the label; error text below the field with an icon, linked via `aria-describedby`; summary of errors at top on submit with links to fields.
- Input height 44px, 16px text, border `--border-input`.
- Components: text, textarea (with character count), select, multi-select (skills as chips), checkbox, radio, toggle (`role="switch"`), date, file upload (drag + button + progress), password (with show/hide toggle; length and breach errors shown on blur or submit, not while typing).
- Password rule shown up front: "At least 12 characters. We check against known breached passwords."

### 6.3 Navigation

| Component | Notes |
|---|---|
| Sidebar | Active item: `--primary-soft` background + 3px left bar + `aria-current="page"`. Badge counts on Applications and Messages. |
| Breadcrumb | Shown on any page deeper than 2 levels |
| Tabs | `role="tablist"`; arrow-key navigation; used for Journey Map (Timeline / Skills / Story) |
| Pagination | 25 rows default; "Showing 1–25 of 143"; `aria-label="Pagination"` |
| Stepper | Onboarding and Apply flows; `aria-current="step"`; step names, not just numbers |

### 6.4 Data Display

- **Table:** sticky header, sortable columns announce state with `aria-sort`, row hover, row selection with checkbox, bulk-action bar appears on selection, mobile: collapses to stacked cards with label/value pairs.
- **Card:** `--surface`, `radius-md`, `shadow-card`, 16–24px padding. Clickable cards have a single focusable link, not nested interactive elements.
- **Status pill:** text + icon + colour (never colour alone).
- **Empty state:** icon, one-sentence explanation, one primary action.
- **Skeleton loader:** for lists and cards that load via HTMX; respects reduced motion (no shimmer).

### 6.5 Feedback

| Component | Behavior |
|---|---|
| Toast | Bottom-right (top on mobile); `role="status"`; auto-dismiss 6s; errors do **not** auto-dismiss |
| Inline alert | `role="alert"` for errors, `role="status"` for info; icon + title + body + optional action |
| Modal | Focus trapped, `aria-modal`, closes on Esc, returns focus to trigger; max width 560px |
| Confirm dialog | Destructive: red button on the right, cancel on the left, default focus on Cancel |
| Tooltip | Appears on hover **and** focus; never holds essential info |
| Progress | Linear bar with text ("Screening 34 of 100"); `role="progressbar"` with values |

## 7. Match Minds–Specific Components

### 7.1 AI Badges

| Badge | Appearance | When |
|---|---|---|
| Generated by AI | ✦ + text, `--ai-soft` bg, `--ai-ink` text | Any AI-written text (rationale, narrative, interview pack, offer draft) |
| Personal details removed | 🛡 + text, `--info-soft` | Anonymized resume view |
| Bias check passed | ✔ + text, `--success-soft` | Rationale passed audit |
| Needs human review | ⚑ + text, `--warning-soft` | Rationale flagged by audit |
| AI delayed | ⏳ + text, `--warning-soft` | Provider slow/down, fallback active |
| Model used | caption: "Model: {name}" with tooltip | Under each rationale (audit provenance) |

### 7.2 Score Card (used on Candidate "Match score" page and Employer "Candidate review")

```
┌────────────────────────────────────────────────────────────┐
│  ◐ 72      Good match                    ✦ Generated by AI │
│  out of 100                              ✔ Bias check passed│
│  ───────────────────────────────────────────────────────── │
│  Matched skills (4)                                         │
│   ✔ Python — "Built Django REST APIs for 3 years"  [view]   │
│   ✔ PostgreSQL — "Designed schema for 12 tables"   [view]   │
│  Missing skills (2)                                         │
│   ✖ Kubernetes — no evidence found in the resume            │
│  Why this score  ▸ (expandable plain-language reasoning)    │
│  Model: openrouter/free · Screened 12 Oct 2026, 14:03       │
└────────────────────────────────────────────────────────────┘
```

Rules:
- Each matched skill shows a **quote from the anonymized resume** (REQ-FR-030). Quotes are visually distinct (indented, `--surface-muted`).
- "No evidence found" is shown literally when evidence is absent. Never hide the row.
- The score number uses `aria-label="Match score 72 out of 100, good match"`.
- Candidate view shows the same card minus employer-only controls (REQ-FR-024).

### 7.3 Cost Estimate Modal

```
┌─ Confirm AI screening ─────────────────────────────────┐
│ Job: Senior Backend Engineer                           │
│ Applications to screen:  100                           │
│ Method: similarity ranking + AI analysis of top 10     │
│ Model: Free tier (openrouter/free)                     │
│ ───────────────────────────────────────────            │
│ Estimated cost:                         $0.00          │
│ Quota after this run:        412 of 500 AI screens     │
│                                                        │
│ Nothing is processed until you confirm.                │
│                         [ Cancel ]   [ Screen 100 ]    │
└────────────────────────────────────────────────────────┘
```

States: free tier ($0.00, calm) · paid model selected (cost shown in `--warning`) · quota exhausted (primary button replaced with "Upgrade plan") · degraded provider (info alert: results will use similarity only).
Default focus on Cancel. Button label states the count ("Screen 100"), never just "OK".

### 7.4 Pipeline Stepper (application status)

`Applied → Screened → Shortlisted → Interview → Offered → Hired`, with `Rejected` shown as a terminal branch. Completed steps: ✔ + text; current: filled + `aria-current="step"`; upcoming: outline. Candidate sees a timestamp per completed step.

### 7.5 Journey Map

Three tabs: **Timeline · Skill evolution · Story**.

```
Timeline tab
 2019 ─────●───────────────●────────────────●──── 2026
          Intern          Junior Dev       Backend Dev
          Acme [A]        [Company B]      [Company C]
 Skills gained on hover/focus: Python · SQL · Django · Docker
 [ View as table ]   ← always visible toggle
```

- Built with Chart.js (canvas) **plus** a real `<table>` alternative (role, period, skills) toggled by "View as table"; screen readers get the table by default via a visually hidden duplicate.
- Each event is keyboard-focusable; arrow keys move between events; Enter opens detail drawer.
- **Skill evolution tab:** stacked area or step chart, one series per skill group; table alternative lists skill, first seen, level.
- **Story tab:** pick a target job (select), "Generate story" (AI action button with cost note), output in an `--ai-soft` card with ✦ label, editable text area, Copy and Save buttons.
- Respect `prefers-reduced-motion`: no animated drawing of lines.

### 7.6 Resume Review (parse check)

Two-column: left = parsed fields (editable); right = original file preview (candidate only). Banner: "We removed your name, email, phone and address before any AI sees your resume." Low-confidence fields get a ⚑ "Please check" marker (resume parsing accuracy risk, RSK-003).

### 7.7 Bias Audit Panel (employer, collapsible)

Shows: result (pass/flag), what was checked (list of rule categories), flagged phrases highlighted in the rationale, and a "Mark as reviewed" action that writes an audit entry. A flagged rationale excludes the candidate from bulk "Shortlist top N" until reviewed.

### 7.8 Quota and Plan Meter

Small meter in employer header/sidebar: "AI screens: 88 of 500 used". Turns `--warning` at 80%, `--danger` at 100%, always with text.

### 7.9 Anonymized Text View

Placeholders render as pill tokens: `[CANDIDATE_NAME]`, `[COMPANY_A]`, `[ROLE_B]` in `--surface-muted` with monospace text, so reviewers see what was masked.

### 7.10 Interview Scorecard

Rows = criteria from the rubric (e.g., technical, communication), each a 1–5 radio group with labels (1 Poor … 5 Excellent), comment field per criterion, overall recommendation (Strong yes / Yes / No / Strong no), Submit. Autosave draft. Radio groups are `fieldset` + `legend`.

## 8. Interaction, Motion and States

### 8.1 Motion

| Use | Duration | Easing |
|---|---|---|
| Hover / focus colour change | 120ms | ease-out |
| Dropdown / tooltip | 150ms | ease-out |
| Modal / drawer | 200ms | ease-in-out |
| Page transition | none (server-rendered) | — |

`@media (prefers-reduced-motion: reduce)` disables all transforms/transitions except colour. No auto-playing animation longer than 5 seconds.

### 8.2 State Matrix (required for every list or data view)

| State | Design requirement |
|---|---|
| Loading | Skeleton rows; `aria-busy="true"` on the region |
| Empty | Icon + sentence + primary action |
| Error | Inline alert with Retry; never a blank area |
| Partial / degraded | "AI delayed" badge; show available data |
| Success | Toast or inline confirmation |
| Permission denied | 403 page with explanation and link home |
| Offline / slow | Retry banner at top (PWA phase) |

### 8.3 HTMX Interaction Patterns

| Pattern | Behavior |
|---|---|
| Inline row update | `hx-post` on Shortlist/Reject; swap row; announce via `aria-live="polite"` region |
| Screening progress | `hx-trigger="every 3s"` polling of progress fragment until complete; stop on done; announce "Screening complete" |
| Search / filter | `hx-trigger="input changed delay:300ms"` with `hx-push-url` so filters survive reload/back |
| Modal content | `hx-get` into dialog container; focus moves to modal heading |
| Form validation | Server-rendered errors swapped in; focus moved to the error summary |
| Optimistic UI | Not used for decisions that write audit entries; wait for server confirmation |

### 8.4 Error Messaging

State what happened, why if known, and what to do. Never show stack traces. Example: "We couldn't read this file. Upload a PDF, DOC or DOCX under 10 MB."

## 9. Accessibility Rules

Target **WCAG 2.1 AA** (REQ-COM-007). Tools in CI: axe-core, pa11y. Build fails on any critical violation.

| Area | Rule |
|---|---|
| Keyboard | Every function reachable; logical tab order; visible focus (2px `--primary` ring + 2px offset) on every interactive element |
| Focus management | Modals trap and restore focus; after HTMX swaps, focus moves to the changed region heading when content replaces the main area |
| Contrast | Text ≥ 4.5 : 1; large text and UI components ≥ 3 : 1 (use Section 3 tokens only) |
| Colour | Never the only signal; icons and text accompany every status colour |
| Forms | Programmatic labels; errors linked by `aria-describedby`; autocomplete attributes (`email`, `current-password`, `new-password`, `one-time-code`) |
| Charts | Table alternative and one-sentence summary for every chart (Journey Map, Analytics) |
| Timers | Assessment timer announced at 50%, 10% and 1 minute via polite live region; user can request extra time notice (flag for admin policy) |
| Motion | Honour `prefers-reduced-motion` |
| Language | `lang` on `<html>`; `lang="bn"` on Bengali content |
| Zoom / reflow | Works at 200% zoom and 320px width without horizontal scroll (tables scroll inside a labelled container) |
| Touch | Targets ≥ 44px |
| Screen reader | Meaningful page `<title>` ("Candidate review · Senior Backend Engineer · Match Minds"); one `<h1>` per page; heading levels not skipped |

Manual test pass before each release: keyboard-only run of the MVP core flow, plus NVDA (Windows) and VoiceOver (iOS).

### 11.4 Performance Budget

| Item | Budget |
|---|---|
| CSS (built, gzipped) | < 30 KB |
| JS (HTMX + Chart.js loaded only on chart pages) | < 100 KB gzipped on non-chart pages |
| Fonts | ≤ 4 WOFF2 files, subset |
| Largest Contentful Paint (mid-range phone, 4G) | < 2.5 s |
| Lighthouse performance | ≥ 90 (REQ-NFR-005) |

Load Chart.js only on Journey Map and Analytics pages.

### 11.5 Icons and Imagery

Use one outline icon set (Lucide or Heroicons, inlined SVG, `aria-hidden="true"` when paired with text). Illustrations are decorative with empty `alt`. No stock photos of people in hiring contexts that could bias perception; prefer abstract shapes.

### 11.6 Localization Readiness (Phase 5)

Allow 30–40% text expansion; avoid fixed-width buttons; no text baked into images; mirror layout for RTL (logical CSS properties: `margin-inline-start`, not `margin-left`); date/number formatting from locale.
