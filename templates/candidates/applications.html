Deviations from the wireframe, all deliberate and reported with the batch: * The "Updated" column is "Applied". `applications` (§5.1) has `created_at`, `screened_at` and `shortlisted_at` but no `updated_at`, and this batch will not invent a column to fill a column heading. The applied date is the one timestamp every row has. * The mobile card list is server-rendered next to the desktop table rather than reflowed from it. `` markup cannot become a card at 360px, and the hidden branch is `display:none`, so a screen reader is given one copy of each application, not two. * The status filter is a plain GET form. S06's `[All ▾]` implies client-side filtering; a server filter works without JavaScript and the URL survives reload and Back. * "Not screened" is the whole match column in Phase 1. Nothing writes `match_score` until Phase 2 (REQ-FR-024), so a band label such as "Good" would be invented from a threshold design.md §3.4 itself marks as unconfirmed. {% endcomment %} {% block title %}My applications · FairFold{% endblock %} {% block description %}Track the jobs you have applied to and their current status on FairFold.{% endblock %} {% block content %}
