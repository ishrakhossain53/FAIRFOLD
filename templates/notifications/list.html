Deliberate deviations from the wireframe, all reported with the batch: * **No "Messages" tab.** W19 draws one, but the documented notification types (`Complete Doc` §C.4) contain no message type: messaging is REQ-FR-043, Phase 3. A tab that can only ever return nothing is the state W28 exists to prevent, so it is omitted until the type exists. The "Applications" tab maps to `application_update`, the type an application event writes. * **No "Notification settings" link.** W19 puts one in the empty state, but page #32's Notifications tab does not exist yet (no settings page does). Rendering a link to a 404 would be a dead control, so the empty state offers the one route that does exist for the recipient's role. * **"Mark all as read" carries the count** in its visible label and only appears when something is unread, as W19's accessibility note requires. * **The unread marker is announced, not just drawn.** The dot is `aria-hidden`; the link text starts with a screen-reader-only "Unread: " so the state survives with images, CSS or colour stripped out. * **Previews are truncated in the markup** (`truncatechars`), not with CSS line clamping: a 500-notification page with full bodies is the screen-reader and performance problem W19 names. * **Pagination.** W19 does not draw it; the page is capped at 20 rows so a recipient with hundreds of notifications does not render them all.
